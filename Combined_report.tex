\section{Section 1 -- Traditional Machine Learning Workflow and Ethics (Dataset 1)}

\noindent\textit{Dataset~1 is binary prediction of professional CSGO match winners from team- and player-level pre-match statistics.} Match outcomes are hard to predict from pre-match rows alone: fifty per cent is guessing, and low-sixties accuracy is already strong; similar work sometimes reaches about sixty-five per cent when neural models or extra context are added. The section covers cleaning, EDA, linear and tree models, CatBoost, K-Means as a sanity check, tuning, feature importance, and a short ethics discussion. Numbers below are on a held-out test set; leakage columns are stripped before training.

\paragraph{Introduction and Objectives.}
The work follows a standard supervised pipeline on tabular match data: define the task, clean the rows, explore patterns, fit several model families, and state clearly what the scores do and do not mean. The emphasis is practical---imputation choices, engineered fields, which models gain accuracy---rather than chasing an isolated leaderboard number. The aim is accuracy clearly above random (50\%) with interpretable models, and an explicit account of where the data and the task fall short.

The implementation uses Python (pandas, NumPy, scikit-learn). Seeds are fixed where it matters so splits and grid searches can be replayed. The inputs are clean columns; the outcomes are not---matches stay partly random even when the features look sensible.

\subsection{1.1\quad Dataset Selection and Problem Definition}

\subsubsection{1.1.1\quad Dataset Overview}

The \textbf{CSGO Match Prediction} set is historical pro matches with team- and player-level pre-match fields (Kaggle: \url{https://www.kaggle.com/datasets/gabrieltardochi/counter-strike-global-offensive-matches}). The file \texttt{csgo\_games.csv} is included with the coursework submission. Raw: three thousand seven hundred and eighty-seven rows, one hundred and seventy columns; after cleaning and engineering, three thousand seven hundred and sixty-three rows and one hundred and seventy-two numeric features.

Table~\ref{tab:features_overview} breaks the columns down.

\textbf{Target variable:} \texttt{winner}. The raw data include draws (twenty-four rows); these were \textbf{excluded} so the task is \textbf{binary}: Team~1 win versus Team~2 win. After removal, class proportions are near-balanced (51.05\% Team~1 / 48.95\% Team~2 on three thousand seven hundred and sixty-three rows), so no oversampling or class weighting is required. Labels are encoded as Team~1 $\rightarrow$ \texttt{0} and Team~2 $\rightarrow$ \texttt{1}; confusion matrices and classification reports below follow that convention.

\paragraph{Unit of analysis and limitations of the snapshot.}
Each row represents one professional match with features aggregated or recorded before the match starts (after leakage columns are removed). The dataset does not contain map veto order, server side, or live economy; those omitted factors contribute residual variance and help explain why accuracy stays in a modest band above chance. The twenty-four excluded draws and any rows failing validation leave three thousand seven hundred and sixty-three matches for modelling. Users of the model should treat predictions as conditional on the feature set actually present in \texttt{csgo\_games.csv}, not on full tactical context.

\subsubsection{1.1.2\quad Problem Definition}

\textbf{Task.} Predict the match winner from \textbf{binary} pre-match rows only (Team~1 vs.\ Team~2 after dropping draws).

In practice a model like this is mainly a planning aid: it can suggest who starts as slight favourite or feed internal discussion---it is not presented as something you could trade on. CS matches stay hard to call from pre-match rows alone; important factors simply are not in the table. With balanced classes, \textbf{fifty per cent} is the chance baseline, so \textbf{sixty per cent test accuracy} shows real learning rather than a useless fit. Other tabular pre-match studies in the literature often plateau near \textbf{sixty-five per cent} once authors add neural nets or extra context, which is the right ballpark for what extra data and modelling can buy. The numbers read as probabilities, not as fixed outcomes.

\paragraph{Success criteria and non-goals.}
The coursework mark rests on a defensible pipeline---data handling, exploration, several model families, tuning, and ethics---not on beating every published benchmark that uses different features or modalities. No claim is made that the model is suitable for betting: the accuracy range rules that out. The useful takeaway is which signals move the needle (\texttt{rank\_diff}, team ratings) and how wide the error bars remain.

Outliers were identified via boxplot inspection of key features (e.g., \texttt{rank\_diff}, ratings), right-skewed distributions in world rankings, and domain knowledge---exceptional player performances (e.g., KDR above two) are valid but rare. Median imputation was chosen for robustness to extremes. Range validation confirmed no impossible values (e.g., negative percentages). After imputation, the dataset contains zero missing values.

\paragraph{Alternative imputations considered.}
Means would pull skewed rating tails toward the middle; kNN imputation can leak structure if neighbours are picked before a proper split, so it was not used ahead of the train/test cut. Full multiple imputation is overkill for a single prediction pipeline at this size; a single completed table is reported. Informal checks (subset of columns to zero or mean-fill) nudged test accuracy by under a point---suggesting the bottleneck is signal, not the imputer.

The submission includes \texttt{csgo\_games.csv} and a short note on the cleaning steps.

\paragraph{Leakage control and reproducibility.}
Standings-style point columns that update after the match are dropped before any fit; otherwise the model could cheat. The split is stratified eighty/twenty on \texttt{winner} so neither side is starved in train or test. \texttt{StandardScaler} is fit on train rows only, then applied to test---no test means in the scaler. Routine practice, but worth stating because the headline numbers depend on it.

\subsubsection{1.2.2\quad Feature Engineering and Scaling}

\textbf{Eight engineered features:}

\begin{table}[H]
\centering
\caption{Engineered features and their rationale.}
\begin{tabularx}{\textwidth}{lX}
\toprule
\textbf{Feature} & \textbf{Description and Rationale} \\
\midrule
\texttt{t1\_avg\_rating}, \texttt{t2\_avg\_rating} & Average HLTV rating across each team's five players. Player rating is the primary individual performance metric in professional CSGO. \\
\texttt{t1\_avg\_impact}, \texttt{t2\_avg\_impact} & Average impact score per team, measuring round-winning contributions beyond kills. \\
\texttt{t1\_avg\_kdr}, \texttt{t2\_avg\_kdr} & Average Kill-Death Ratio per team, a standard measure of individual survivability and lethality. \\
\texttt{rank\_diff} & Difference in world rankings (\texttt{t1\_world\_rank} $-$ \texttt{t2\_world\_rank}). Captures the relative competitive strength gap. \\
\texttt{h2h\_advantage} & Difference in head-to-head win percentages. Captures historical team-versus-team performance patterns. \\
\bottomrule
\end{tabularx}
\end{table}

Tournament point columns \texttt{t1\_points} and \texttt{t2\_points} were dropped to prevent \textbf{data leakage}, as they reflect standings updated after matches and would not be legitimate pre-match inputs. All one hundred and seventy-two retained numerical features were standardised using \textbf{StandardScaler}; the target was encoded (\texttt{t1}$\rightarrow$0, \texttt{t2}$\rightarrow$1). The final split is three thousand and ten training samples and seven hundred and fifty-three test samples (stratified eighty/twenty).

\paragraph{Rationale for engineered aggregates.}
Averaging players into team-level stats tracks strength without baking in roster IDs that churn between seasons. \texttt{rank\_diff} and \texttt{h2h\_advantage} describe the \textit{matchup} (``better rank on paper but bad h2h''), not raw ranks in isolation. The engineered block was kept deliberately small: enough signal for logistic regression and trees without a hundred interaction terms.

\subsubsection{1.3.5\quad Potential Biases Identified in the Data}

\begin{enumerate}[leftmargin=1.5em]
    \item \textbf{Temporal Bias:} The dataset spans multiple competitive seasons. CSGO meta-game shifts (strategy, weapon balance, map pool) mean that patterns from earlier years may not generalise to more recent matches.
    \item \textbf{Team Representation Bias:} Top-ranked teams compete more frequently and therefore dominate the dataset. The model may be poorly calibrated for underrepresented lower-ranked or regional teams.
    \item \textbf{Ranking System Bias:} World rankings are a lagging indicator and do not immediately reflect roster changes or strategic pivots, introducing systematic noise in the most predictive feature.
    \item \textbf{Coverage bias:} The sample is weighted toward high-tier international play visible on HLTV; casual or regional events may be underrepresented, so error rates may differ by competition tier.
    \item \textbf{Label definition:} The target is match winner, not round differential or map score; close bo1 upsets and comfortable bo3 wins are treated identically once the match result is recorded.
\end{enumerate}

\paragraph{Link from EDA to modelling choices.}
A line of best fit in rank/rating space already separates winners to some extent; what remains is noise. Logistic regression should therefore stay competitive, forests may add a few points, and very large models cannot invent signal---the inputs omit veto, maps, and same-day form. Single player statistics should not be read as sole drivers when team averages subsume much of the same information.

\subsection{1.4\quad Model Development and Evaluation}

\subsubsection{1.4.1\quad Models Trained}

Three broad model families were trained:

\paragraph{Logistic Regression.} Linear model on the log-odds:
\[
\log\frac{P(y=1|\mathbf{x})}{1-P(y=1|\mathbf{x})}
=
\mathbf{w}^\top \mathbf{x} + b.
\]
It is the obvious first model: fast, inspectable, and probabilistic.

\paragraph{Decision Tree.} Single tree with Gini splits, $G(t) = 1 - \sum_c p(c|t)^2$, \texttt{max\_depth}=10, \texttt{min\_samples\_split}=20 to keep it from memorising. Impurity-based importances come for free.

\paragraph{K-Means.} Required unsupervised check: $k=2$ clusters in feature space, objective $\sum_i \sum_{\mathbf{x} \in C_i} \|\mathbf{x} - \boldsymbol{\mu}_i\|^2$. ARI against true winners is $\approx 0$, so unsupervised geometry does not recover the label---supervised models are doing real work, not picking up a trivial cluster structure.

\paragraph{Heavier models (Figure~\ref{fig:models_accuracy}).}
The experiments also include \textbf{Random Forest} (default and \GridSearchCVname{}-tuned), \textbf{XGBoost}, \textbf{LightGBM}, \textbf{CatBoost}, and \textbf{logistic regression with \texttt{SelectFromModel}} (fifty features from forest importance), plus voting/stacking runs where included in the comparison chart. On the test split \textbf{CatBoost} leads; tuned forests and sparse LR sit underneath. Boosting picks up small non-linearities; nothing approaches ninety per cent because the labels stay noisy.

\subsubsection{1.4.2\quad Evaluation Metrics}

For classification models:

\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Accuracy:} $\frac{TP + TN}{TP + TN + FP + FN}$ --- proportion of correctly classified matches.
    \item \textbf{Precision / recall / F1 (per class):} scikit-learn reports metrics for each label. With encoding \texttt{t1}$\rightarrow$0 and \texttt{t2}$\rightarrow$1, the conventional ``positive'' class in one-vs-rest terms is label~\texttt{1} (Team~2). Precision is $\frac{TP}{TP+FP}$ for that class; recall is $\frac{TP}{TP+FN}$.
    \item \textbf{F1-Score:} harmonic mean of precision and recall for the class of interest; per-class and summary values appear alongside accuracy in the results tables.
\end{itemize}

For K-Means:
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Adjusted Rand Index (ARI):}
    {\small
    \[
    \mathrm{ARI}
    =
    \frac{\mathrm{RI}-\mathbb{E}[\mathrm{RI}]}{\max(\mathrm{RI})-\mathbb{E}[\mathrm{RI}]}
    \]
    }
    where RI is the Rand Index. Agreement between cluster assignments and true labels, corrected for chance. ARI $\approx 0$ indicates random assignment.
    \item \textbf{Silhouette Score:} $s(i) = \frac{b(i) - a(i)}{\max(a(i), b(i))}$, where $a(i)$ is mean intra-cluster distance and $b(i)$ is mean nearest-cluster distance. Values near 1 indicate well-separated clusters.
\end{itemize}

\paragraph{Interpreting the metrics.}
With balanced classes, accuracy is an honest headline; precision and recall per label (\texttt{0}/\texttt{1}) are still examined for asymmetry. F1 compresses that trade-off for the positive class (label~\texttt{1}). For K-Means, ARI scores clusters against \texttt{winner}; silhouette is reported as a geometric sanity check without using labels in the fit.

\subsubsection{1.4.6\quad Interpretation}

Matches remain partly random in the manner of live sport rather than deterministic spreadsheet logic. Sixty per cent accuracy is therefore a substantial result against fifty per cent chance, and published ceilings near sixty-five per cent underline how little headroom remains. None of that renders the model suitable for betting; Section~1.5 covers misuse.

\subsubsection{1.4.7\quad Limits of the reported evaluation}

Accuracy and F1 summarise classification quality at a 0.5 threshold; they do not fully describe probability behaviour. Boosting libraries emit calibrated-looking scores in some settings, but tabular match data with overlapping classes can still yield miscalibrated probabilities unless Platt scaling or isotonic regression is fit on held-out data. Stakeholders who care about ranked risk (``top ten matches to watch'') would need calibration checks beyond the confusion matrices shown.

The feature set is also intentionally narrow relative to what a human analyst sees before a match. Map veto order, per-map strength, recent roster moves with only a few games played, and communication-heavy intangibles do not appear in \texttt{csgo\_games.csv}. The models therefore learn from what is available, not from everything that influences a result; the gap between sixty-one per cent and a hypothetical ceiling is partly missing data, not only algorithm choice. Finally, class balance removes the need for class weights in training, which simplifies interpretation but means the pipeline has not been stress-tested on artificially rebalanced samples---an acceptable simplification here, but not if the deployment population shifts toward one-sided matchups.

\subsubsection{1.4.8\quad Plausible extensions (tabular only)}

Within the same tabular setting, several extensions are straightforward to describe even if they were not all implemented end-to-end. Time-based splits and rolling retraining would align evaluation with how odds and rankings actually evolve. Team-ID or roster-ID features could be added with strong regularisation to pool information across seasons without treating every player column as a free parameter. Interaction terms between \texttt{rank\_diff} and head-to-head history could be tested explicitly rather than leaving all interactions to tree ensembles. For transparency, partial dependence or SHAP-style summaries on the CatBoost model would complement impurity and gain-based importances. None of these steps changes the fundamental noise in match outcomes; they mainly tighten estimation and make failure modes easier to audit.

Nested cross-validation would separate hyperparameter selection from final performance estimation more cleanly than a single grid search followed by one test hit. The computational cost rises sharply with boosting grids, which is why the report leans on three-fold CV on the training fold and a single held-out test set for headline reporting. If budgets allow, repeated stratified splits or bootstrap optimism correction would quantify how fragile the two-point gap between CatBoost and logistic regression really is.

\subsection{1.5\quad Ethical Considerations}

\subsubsection{1.5.1\quad Potential Biases}

\paragraph{Temporal and concept drift.}
The rows span several competitive years; patches, maps, and formats shift. A model trained on everything mixes old and new regimes, so the feature-to-label map drifts even when each row looks valid.

\paragraph{Representation and coverage.}
Top teams show up more often, so errors are optimised under a distribution that favours elite play. Lower tiers, smaller regions, or unusual rosters can be under-sampled; probabilities may be off where the data are thin.

\paragraph{Ranking system and lag.}
HLTV-style ranks move slowly. Roster upgrades or a new coach can leave the model looking at stale \texttt{rank\_diff} values exactly when humans are uncertain too.

\paragraph{Data collection and aggregation.}
Public CSVs lean on tier-one LANs and big online leagues; scrims, comms, and morale never appear. Averaging players hides roles (entry vs.\ support) and IGL impact, so identical aggregates can describe different teams in practice.

\subsubsection{1.5.2\quad Mitigation Strategies}

\paragraph{Operational mitigations.}
Models should be retrained on rolling windows, refreshed after major patches, and augmented with short ``form'' windows when data allow. Evaluation should slice by tier or region so one headline accuracy does not hide poor subgroups. Relative features (\texttt{rank\_diff}, rating gaps) usually outperform raw rank integers alone.

\paragraph{Governance and responsible use.}
A simple linear model should remain available alongside CatBoost so failures expose interpretable signs. Any deployment beyond coursework should log predictions and outcomes and review poorly performing slices. Player statistics may constitute personal data in some jurisdictions and warrant the same safeguards as other sensitive fields.

\paragraph{Gambling and misuse.}
The model must \textbf{not} be used for betting. Sixty-one per cent exceeds chance but does not constitute an edge once bookmaker margins and line movement are accounted for. Uncertainty should be communicated when probabilities sit near one half.

\paragraph{Transparency.}
Provenance of the CSV, columns removed, and engineered features should be documented so readers know what the reported scores condition on.

\subsubsection{1.5.3\quad Key Recommendations}

\begin{enumerate}[leftmargin=1.5em]
    \item \textbf{CatBoost} (or \textbf{LR with feature selection} when interpretability dominates) should be used only as decision-support, not as an autonomous decision system.
    \item Models should be \textbf{retrained} on sliding windows of recent matches; post-patch degradation should be monitored.
    \item Metrics should be \textbf{sliced} by team tier, region, and online versus LAN when sample sizes allow.
    \item Model outputs should be \textbf{paired} with human review for roster changes and format changes.
    \item Betting and gambling use cases should be \textbf{prohibited} in product terms; the restriction should be documented for end users.
\end{enumerate}

\paragraph{Closing remarks (Dataset~1).}
Section~1 documents cleaning with leakage removed, a compact engineered block, EDA, linear and tree models with K-Means as a check, tuning tables, and CatBoost leading on the test split. The limitations listed above belong in the main narrative: they mark where the pipeline ceases to be reliable. Together, that constitutes the Dataset~1 contribution of this coursework.

What we hand in alongside this PDF is meant to be rerunnable: the raw CSV, the cleaning code or notebook, the fitted scaler, and any saved models, plus the figure files that appear in the report. Someone could in principle reproduce the tables and plots from those files; the write-up explains the choices, but the numbers ultimately come from running that code. Recording library versions (for example scikit-learn and CatBoost) matters because minor updates can change default behaviour and make old results hard to match.

\subsection{2.1\quad Text Dataset Selection and Preprocessing}\label{sec:nlp_preprocess}

For this part of a project, we selected a publicly available dataset containing Steam reviews for the game Counter-Strike: Global Offensive (CS:GO) taken between 31st January 2023 to 1st March 2023. The dataset is available on Kaggle: \url{https://www.kaggle.com/datasets/noahx1/csgo-steam-reviews}.

It contains 15,640 user reviews, each labelled with a binary variable \texttt{voted\_up}, where 1 represents a positive recommendation and 0 represents a negative recommendation. The dataset is highly imbalanced, with approximately 89\% positive reviews and 11\% negative reviews, which makes it suitable for a binary sentiment analysis task. Reviews are typically very short, with an average length of around five to six words and approximately 47 characters per review, reflecting the concise nature of many Steam user comments.

Before training the models, several preprocessing steps were applied to improve data quality. First, reviews with missing or empty text were removed. Reviews written mostly in non-Latin script, for example Cyrillic or ASCII art, were filtered out by computing a Latin character ratio and removing reviews with a ratio below 0.15. The remaining reviews were then cleaned by converting all text to lowercase, removing any URLs, HTML tags, punctuation, and non-alphabetic characters using regular expressions. The text was tokenized, and common English stop words were removed using the NLTK stop word list to reduce noise and improve feature quality. Reviews that became empty after cleaning were also discarded. The cleaned text was stored as a new feature and the sentiment label was converted into a binary target variable for model training.

For feature representation, pre-trained word embeddings from Global Vectors for Word Representation (GloVe) were used. Specifically, the GloVe 6B dataset with 100-dimensional vectors was downloaded from the Stanford NLP repository. Each word in the vocabulary was mapped to its corresponding embedding vector to create an embedding matrix, which was then used to initialise the embedding layer in the neural network models. Using pre-trained embeddings allows the model to leverage semantic relationships learned from large text corpora, improving generalization and enabling the model to capture contextual similarities between words.

\paragraph{Train, validation, and test discipline.}
After cleaning, the data are partitioned into training, validation, and held-out test sets. The validation split drives early stopping, learning-rate reduction, and hyperparameter selection; the test set is used only for final evaluation figures and tables. That separation mirrors Section~1's insistence on fitting scalers on training data only: here, token frequencies and embedding alignment are computed from training corpora statistics so that validation and test reviews do not inflate vocabulary counts or distort rare-word handling.

\paragraph{Vocabulary and OOV behaviour.}
Limiting vocabulary to the twenty thousand most frequent tokens strikes a balance between coverage of CSGO slang (``toxic'', ``smurfs'', map names) and matrix size. Out-of-vocabulary tokens map to a reserved index; random initialisation for missing GloVe rows lets fine-tuning recover domain usage during back-propagation. The Latin-character filter trades recall of multilingual community content for a more homogeneous token stream, which is an explicit scope limitation: non-English reviews are largely excluded.

\subsection{2.2\quad Deep Learning Model Implementation}\label{sec:nlp_model}

Following the preprocessing and feature representation, deep learning models were designed and trained to perform sentiment classification on the CS:GO Steam reviews dataset. The objective of the models is to predict whether a review expresses a positive or negative sentiment, based on the binary label. Text reviews represent sequential data; neural network architectures capable of modelling word order and contextual relationships were used.

To prepare the input for the neural networks, a custom vocabulary was constructed from the cleaned review corpus. The vocabulary size was limited to the 20,000 most frequent words, ensuring that the models focus on the informative tokens while keeping computational complexity manageable. Each review was converted into a sequence of integer indices representing the words in the vocabulary. Because neural networks require inputs of consistent length, the sequences were padded or truncated to a maximum length of 50 tokens, allowing the models to process all reviews in a fixed format.

For word representation, the pre-trained GloVe embeddings described in the previous section were used as the basis for the embedding layer. The embedding matrix was aligned with the custom vocabulary so that each token index corresponds to its respective 100-dimensional vector. Words not found in the pre-trained embedding set were assigned small random vectors so that they could still be learned during training. The embedding layer was configured with trainable parameters, allowing the neural network to fine-tune the vectors and adapt them to domain-specific language commonly found in gaming reviews.

To evaluate different approaches to modelling textual sentiment, three neural network architectures were implemented and compared: a Simple Recurrent Neural Network (RNN), a Long Short-Term Memory (LSTM) network, and a hybrid Convolutional Neural Network with Bidirectional LSTM (Conv1D + BiLSTM) model.

The Simple RNN model serves as a baseline architecture. It consists of an embedding layer followed by a SpatialDropout1D layer, a SimpleRNN layer with 128 units, a fully connected dense layer with ReLU activation, and a final output layer with a sigmoid activation function. The SpatialDropout1D layer randomly disables entire embedding dimensions during training, helping to regularise the embedding representation and reduce overfitting. The SimpleRNN layer processes the text sequentially and learns patterns based on word order. However, traditional RNNs can struggle to retain information from earlier parts of a sequence due to the vanishing gradient problem.

To address this limitation, a second architecture replaces the SimpleRNN layer with an LSTM layer. LSTMs introduce internal gating mechanisms that regulate the flow of information through the network. These gates allow the model to retain important contextual information across longer sequences, making LSTMs particularly suitable for natural language processing tasks. In this architecture, the LSTM layer is followed by a dense layer with ReLU activation, a Dropout layer for regularisation, and a final sigmoid output layer that predicts the probability of a positive review.

We decided to include a more advanced architecture combining convolutional and recurrent neural network techniques. This model consists of an embedding layer, SpatialDropout1D regularisation, a Conv1D layer with 128 filters and a kernel size of three, a Bidirectional LSTM layer, GlobalMaxPooling1D, and several fully connected layers. The convolutional layer acts as a feature extractor by identifying local n-gram patterns in the text, such as short phrases that strongly suggest sentiment. The Bidirectional LSTM processes the review sequence in both forward and backward directions, allowing the model to capture contextual information from both preceding and following words in the sequence. This helps the network understand more complex sentiment expressions.

The output of the Bidirectional LSTM is passed to a GlobalMaxPooling1D layer, which extracts the strongest feature signals across the sequence and converts the variable-length sequence representation into a fixed-length feature vector. This representation is then processed by a dense layer with ReLU activation, followed by Batch Normalization, which stabilises and accelerates training by normalising intermediate activations. A Dropout layer is also applied to reduce overfitting by randomly deactivating neurons during training. Finally, a single neuron with a sigmoid activation function produces the probability that the review expresses positive sentiment.

\paragraph{Validation accuracy across architectures.}
After training each architecture with the same preprocessing, tokenisation, and class-weighting scheme, validation-set accuracy and per-metric breakdowns were compared before committing to a full grid search on the strongest design. Figure~\ref{fig:nlp_arch_accuracy} summarises the pattern: the Conv1D + BiLSTM stack improves on the plain RNN and LSTM baselines, matching the qualitative expectation that local n-gram features and bidirectional context help on short, noisy Steam text.

All models were trained using the binary cross-entropy loss function, which is appropriate for binary classification tasks. The Adam optimiser was used due to its efficiency and adaptive learning rate capabilities. Since the dataset is highly imbalanced, with a significantly larger number of positive reviews than negative ones, we decided to implement a class weighting during training to ensure that minority class samples were given appropriate importance.

\paragraph{Loss and class weights (conceptual).}
Binary cross-entropy for label $y \in \{0,1\}$ and predicted probability $\hat{p}$ is $-\bigl(y\log \hat{p} + (1-y)\log(1-\hat{p})\bigr)$, averaged over mini-batches. Class weights rescale contributions so that a misclassified rare negative review contributes similarly to total gradient magnitude as several easy positives, preventing collapse to the trivial always-positive predictor. This is complementary to macro F1 evaluation: weights shape training; F1 shapes how we judge success.

To improve training stability and prevent overfitting, early stopping was implemented. This technique monitors the validation loss during training and stops the training process if the model's performance stops improving for several epochs. In addition, the final model incorporated a learning rate scheduling strategy using ReduceLROnPlateau, which automatically reduces the learning rate when validation performance plateaus. This allows the model to make finer adjustments to its weights during later training stages.

In order to further improve model performance, several hyperparameters were automatically tuned. A grid search approach was used to explore different combinations of batch size, dropout rate, and learning rate. Specifically, batch sizes of 64, 128, and 256, dropout rates of 0.1, 0.2, and 0.3, and learning rates of 0.001, 0.0005, and 0.0001 were evaluated. Each combination of parameters was tested using the Conv1D + Bidirectional LSTM architecture, which showed the strongest initial performance.

For each hyperparameter configuration, the model was trained for several epochs and evaluated using multiple performance metrics, including accuracy, precision, recall, and macro F1-score. Because the dataset is imbalanced, the macro F1-score was used as the primary metric, as it provides a balanced measure of performance across both classes. The grid search procedure recorded the results for each configuration and selected the parameter combination that achieved the highest macro F1-score.

The final model therefore uses the Conv1D + Bidirectional LSTM architecture with the optimal hyperparameters identified through grid search. This model integrates pre-trained word embeddings, convolutional feature extraction, bidirectional sequence modelling, and regularisation techniques such as dropout and batch normalization. Through this combination of architectural design and hyperparameter optimisation, the model is able to effectively capture both local sentiment patterns and broader contextual relationships within the review text.

\paragraph{Reproducibility and compute.}
Neural training is stochastic (mini-batch order, dropout masks, weight initialisation). Random seeds for NumPy and TensorFlow are fixed where applicable for reproducibility. Training time scales with sequence length (fifty tokens), vocabulary cap, and batch size; grid search multiplies wall-clock cost, which is why the search is restricted to the strongest architecture rather than repeating the same grid on weaker RNN baselines.

Together these give a view of fit, generalisation, and class balance.

\noindent\textbf{Headline test-set scores (held-out split).} The final Conv1D + BiLSTM checkpoint achieves \textbf{88\%} overall accuracy on two thousand eight hundred and eighty-seven test reviews. \textbf{F1-scores} (the harmonic mean of precision and recall for each class) are: \textbf{negative class F1 = 0.42} (precision 0.42, recall 0.43); \textbf{positive class F1 = 0.93} (precision 0.93, recall 0.93); \textbf{macro-averaged F1 = 0.68}; \textbf{weighted-averaged F1 = 0.88}, matching the weighted precision and recall in Figure~\ref{fig:nlp_report}. \subsubsection{Strengths of the approach}

The evaluation highlights several strengths of the implemented sentiment classification system. First, the custom preprocessing pipeline provides full control over the data cleaning and tokenisation process, ensuring that noisy or irrelevant content is removed before training. This improves the quality of the textual input provided to the model. Second, the comparison of multiple neural architectures allows the most effective model design to be identified. Among the tested models, the Conv1D + Bidirectional LSTM architecture demonstrates superior performance by combining local pattern extraction with contextual sequence modelling. Third, the use of grid search hyperparameter tuning and class weighting helps mitigate the effects of the strong class imbalance in the dataset. By adjusting batch size, learning rate, and dropout rate, the training process identifies parameter combinations that maximise macro F1-score; the resulting \textbf{test macro F1 is 0.68} with \textbf{class F1 scores 0.42} (negative) and \textbf{0.93} (positive), as tabulated in Figure~\ref{fig:nlp_report}. Another advantage is the use of trainable GloVe embeddings, which allow the model to refine pre-trained word representations and adapt them to domain-specific language commonly found in gaming reviews. Finally, the evaluation process itself is comprehensive. By combining learning curves, confusion matrices, classification metrics, and threshold analysis, we obtain clear visual confirmation of model behaviour, as illustrated in Figures~\ref{fig:nlp_learning}, \ref{fig:nlp_cm}, \ref{fig:nlp_report}, and~\ref{fig:nlp_threshold}.

\subsubsection{Limitations}

Despite the strong performance of the model, several limitations remain. Sentiment classification models based on recurrent networks may struggle to interpret sarcasm, irony, or complex linguistic structures, which are common in informal online reviews. For example, phrases that appear positive in isolation may actually convey negative sentiment depending on context. In addition, the dataset contains very short reviews and potentially noisy labels, which can limit the maximum achievable performance. Extremely brief comments may lack sufficient context for accurate sentiment prediction, even when advanced neural architectures are used.

\paragraph{Platform dynamics and label semantics.}
Steam's \texttt{voted\_up} flag reflects whether the user recommends the game, not a fine-grained sentiment score. A negative recommendation can mean disapproval of recent patches, anti-cheat friction, or toxicity in matchmaking---topics that overlap only partially with the literal text of a five-word review. Review waves tied to major updates (``review bombing'') can shift the joint distribution of text and labels without the language model seeing the external event, hurting generalisation across time. Community norms also evolve: memes and slang that read as negative to a human may lack negative training examples.

\paragraph{Ethical deployment.}
Automated sentiment or moderation systems trained on public reviews can entrench majority opinions and mis-handle non-English or coded language unless explicitly tested. Any production use should keep humans in the loop for appeals, publish error rates by demographic or regional slice where feasible, and avoid using model scores as the sole reason to shadow-ban or sanction accounts.

\subsubsection{Future improvements}

Future work could explore the use of transformer-based models, such as Bidirectional Encoder Representations from Transformers (BERT). Transformer architectures use self-attention mechanisms to capture relationships between words across an entire sentence simultaneously. Pre-trained transformer models also incorporate rich contextual embeddings learned from very large corpora, which could significantly improve performance on nuanced sentiment expressions and sarcasm. Integrating such models could further enhance the system's ability to understand complex review language and achieve higher classification accuracy.

\subsubsection{Summary}

Overall, the evaluation demonstrates that the developed sentiment classification system performs effectively on the CS:GO Steam reviews dataset: \textbf{88\%} test accuracy, \textbf{macro F1 of 0.68}, \textbf{weighted F1 of 0.88}, and class F1 scores \textbf{0.42} (negative) and \textbf{0.93} (positive) on the held-out set---the spread between macro and weighted F1 illustrates the skewed class distribution. Standard practice is followed throughout: learning curves (Figure~\ref{fig:nlp_learning}), a confusion matrix (Figure~\ref{fig:nlp_cm}), per-class classification metrics (Figure~\ref{fig:nlp_report}), and threshold optimisation (Figure~\ref{fig:nlp_threshold}). These techniques provide quantitative and visual insight into model performance and justify the chosen architecture and hyperparameters. Together, they confirm that the final Conv1D + Bidirectional LSTM model captures meaningful sentiment patterns in the review text; balanced performance across classes remains limited by the rarity of negative reviews despite class weighting.

\subsection*{Synthesis across Dataset~1 and Dataset~2}

Both parts of this coursework exercise the same scientific habits under different data regimes. Dataset~1 foregrounds \textit{leakage control}, \textit{calibrated expectations} about \textbf{gambling-like} noisy targets, and \textit{model choice under a tabular ceiling}: gradient-boosted trees (CatBoost) edge out logistic regression with feature selection. Absolute accuracy sits near \textbf{sixty-one per cent}---\textbf{good} against a fifty per cent baseline and close to informal \textbf{sixty-five per cent} best-case benchmarks reported on similar match models (including neural-network approaches in some studies)---showing that better algorithms help but cannot remove inherent match randomness. Dataset~2 foregrounds \textit{representation learning} (embeddings, convolutions, recurrence), \textit{class imbalance}, and \textit{richer evaluation dashboards} (macro F1 $\approx$~0.68 vs.\ weighted F1 $\approx$~0.88 on Steam reviews, threshold sweeps) because headline accuracy alone would mask collapse on negative reviews.

Methodologically, both streams rely on held-out evaluation, explicit handling of missing or dirty inputs, and ethical reflection on who is represented in the data and how predictions might be misused. Practitioners should not export the match predictor into high-stakes wagering contexts, and should not export the sentiment model into fully automated moderation without human oversight, especially given sarcasm and label noise. Future extensions might unify the themes by building multi-input models (tabular team stats plus community sentiment features) while retaining the governance lessons from Sections~1.5 and~2.3.

\paragraph{Checklist for replication.}
A reader who wishes to reproduce our conclusions should: (one) start from the same Kaggle exports and verify row counts after cleaning; (two) confirm removal of \texttt{t1\_points} and \texttt{t2\_points}, exclusion of draws, and the target row counts (three thousand seven hundred and sixty-three) before training; (three) refit \texttt{StandardScaler} on train only; (four) reuse the stratified eighty/twenty split seed if exact duplication is required; (five) for NLP, rebuild vocabulary from train reviews only and re-download matching GloVe files; (six) compare final neural-network metrics on the held-out test set to the values reported in Section~2.3. Small numerical drifts across machines are normal for deep learning but should not change qualitative conclusions if seeds and library versions align.

\paragraph{What we would do with more time.}
For structured match data, hierarchical models that partially pool by team ID could exploit repeated matchups but require careful regularisation to avoid overfitting small rosters. Map-specific submodels would need sufficient samples per map. For text, transformer fine-tuning (e.g., small BERT or DistilBERT) with class-weighted loss would be the next accuracy-focused step, at higher GPU cost. For both problems, deployment-oriented work would emphasise calibration (Platt scaling or isotonic regression on validation outputs) and continuous monitoring dashboards rather than marginal gains in offline accuracy.
